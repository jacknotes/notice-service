# Notice Service · 发送日志列表列精简设计

> 日期：2026-08-25
> 状态：已批准（brainstorming 会话，用户选定方案 A）
> 修订：v1

## 1. 背景与目标

### 1.1 现状（已核实）

`web/src/views/Logs.vue`「发送日志」列表当前共 12 列：

| # | 列 | 宽度 | 备注 |
|---|---|---|---|
| 1 | 展开按钮 | 默认(~48px) | 展开行内已有 触发来源/标题/发送内容/请求/响应/错误信息 |
| 2 | ID | 72 | |
| 3 | 标题 | min 180 | `show-overflow-tooltip` |
| 4 | 任务 | min 160 | |
| 5 | 渠道 | min 150 | |
| 6 | 触发 | min 150 | 展开行「触发来源」已有 |
| 7 | 触发 IP | min 110 | 展开行已有 |
| 8 | 状态 | 100 | |
| 9 | 重试 | 80 | 详情页 `LogDetail.vue` 已展示 |
| 10 | 错误信息 | min 200 | 成功行为"—"；展开行已有 |
| 11 | 时间 | min 170 | ← 用户反映被遮挡 |
| 12 | 操作 | 140 `fixed="right"` | |

**根因**：列最小宽度合计约 **1570px**；在展开侧边栏(220px)的 1440 屏上，表格实际可用约 **1130px**。宽度不足 → 必然横向滚动；而「操作」列 `fixed="right"` 固定在右侧，把倒数第二列「时间」挤到固定列底下，无法完整显示。

### 1.2 目标

- 去掉 4 个低价值/信息重复的列（触发、触发 IP、错误信息、重试），使表格在常见屏宽下**无需横向滚动、所有列完整显示**。
- 信息零丢失：被删列的信息在展开行 / 详情页中仍可查看。
- 用户明确要求：**重试次数删除后仍在详情中可显示**。

### 1.3 非目标（YAGNI）

- 不改任何后端接口、不改数据模型、不改导出 CSV（后端按筛选条件导出，与表格列无关）。
- 不做列宽度记忆/自定义列显隐/拖拽调宽等增强功能。
- 不动 `LogDetail.vue`（其已展示重试次数、触发方式/人/IP、错误信息）。

## 2. 总体方案

仅改 `web/src/views/Logs.vue`（模板列定义 + 展开行新增重试次数 + 微调宽度），无后端改动。

### 2.1 删除 4 个列

从 `<el-table>` 模板中移除：

- `触发`（`prop="trigger_type"`，含 `sortable="custom"`）
- `触发 IP`（`prop="trigger_ip"`，含 `sortable="custom"`）
- `错误信息`（`prop="error_msg"`）
- `重试`（`prop="retry_count"`，含 `sortable="custom"`）

### 2.2 展开行补「重试次数」

在展开行模板（现有 触发来源/标题/发送内容/请求/响应/错误信息 各 `detail-block` 之后）新增一个 `detail-block`：

```
<div v-if="row.retry_count" class="detail-block">
  <span class="detail-label">重试次数</span>
  <span class="mono">{{ row.retry_count }}</span>
</div>
```

`retry_count` 未定义时显示 `0`，与详情页 `LogDetail.vue` 的 `{{ log.retry_count ?? 0 }}` 保持一致。用户要求删除列后仍可见，故补在此处。

### 2.3 「操作」列去掉 `fixed="right"`

表格不再横向滚动后，固定列无必要，去掉以避免任何覆盖/重叠问题。其余属性（width 140、align center、按钮）不变。

### 2.4 保留列宽度核对

调整后 8 列：

- 展开 ~48 + ID 72 + 标题 180 + 任务 160 + 渠道 150 + 状态 100 + **时间 170** + 操作 140 ≈ **1020px**

小于可用宽度 ~1130px，`el-table` 的 fit 行为会把富余宽度自动分配给 `min-width` 列（标题/任务/渠道/时间略微变宽），所有列完整显示、无横向滚动。

### 2.5 不影响项

- 关键词搜索（`keyword`）按数据字段（task/channel/subject/content/error_msg/trigger_by/trigger_ip/trigger_type）过滤，与列显隐无关，删列不破坏搜索。
- 后端排序白名单中被删的 `trigger_type/trigger_ip/retry_count` 仅不再可点击排序，无影响。
- 导出 CSV 不受影响。

## 3. 验收标准

1. `/logs` 页面表格显示 8 列（展开、ID、标题、任务、渠道、状态、时间、操作）。
2. 展开行可见「重试次数」。
3. 在 1440 宽屏（展开侧边栏）下表格**无横向滚动条**，时间列完整可见。
4. 关键词搜索、状态/任务/日期筛选、排序、导出 CSV 行为不变。
5. `pnpm build`（web）通过，无 TS 报错。
